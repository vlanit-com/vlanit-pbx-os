# Changelog VLANit PBX OS

Формат: секция `## X.Y.Z (дата)` на релиз. Workflow build-iso при публикации
релиза по тегу `vX.Y.Z` берёт текст секции из этого файла как описание релиза
(идея #11: тег не меняется, описание — часть исходников на коммите тега).

## 1.3.2 (не выпущена)

- Установщик: оценка «осталось ~N мин» переписана с линейной формулы на
  калиброванные длительности этапов (таблица в progress.sh из
  фактических прогонов стенда, поправка скорости по прошедшему времени) —
  раньше почти всегда показывала «~0 мин», т.к. скачковая шкала
  завышала прогресс на долгих этапах.
- Установщик: пароль ОС короче 8 символов и невалидный часовой пояс
  возвращают к повторному вводу вместо обрыва установки с чёрным экраном
  (issue #44, спека 1.3.2-issues-44-45).
- Загрузка: vlanit-atc-password-heal больше не WantedBy=multi-user.target
  (теперь mikopbx.service) — не задерживает multi-user ~2,5 минуты на
  медленной загрузке и не откладывает vlanit-firstboot (issue #45).
- Версии: строка «устанавливается только на UEFI» в мастере теперь из
  release-manifest (был литерал «1.0»); scripts/test-qemu.sh: имя ISO и
  Application ID из build.yaml (без литералов); vlanit-doctor печатает
  версию ОС в шапке отчёта (аудит версий 1.3.2).

- Установщик: экран установки — gauge-прогресс со статусами этапов и
  оценкой «осталось ~N мин» (калиброванные длительности этапов, не
  «~0 мин»); autoinstall без изменений: вывод в serial для агента.
  Суб-прогресс по du для долгих этапов пробовал и УДАЛИЛ в той же
  итерации: фоновый du по целевой ФС дважды зависал навсегда (зеркало
  и linear). Спека: docs/specs/1.3.2-installer-ui.md.
- Установщик: фирменная тема псевдографики (installer/dialogrc: тёмный
  фон, золотые акценты; backtitle «VLANit PBX OS <версия> — установка»)
  на всех диалогах мастера, включая gauge и экраны ошибок.
- Диски: root-LV в процентах от usable-диска — installer.system_size_pct:
  25 вместо фиксированных 40960 МиБ; Data — остаток, минимум 8 ГиБ
  (проверка до деструктивных операций). Тот же ключ читают расчёт LV,
  минимум диска и autoinstall-переопределение (малый профиль стенда
  mirror: 25 % на 13 ГиБ ≈ 3 ГиБ root).
- Установщик: суб-прогресс по du (развёртывание, импорт образа) —
  только интерактив на одном диске; на зеркале RAID1 чтения Btrfs во
  время фонового initial sync зависают (dm-raid1 idle × btrfs commit,
  issue #43 — найдено стендом 1.3.2, gauge встал на развёртывании).

- Сборка: версия в строках артефактов (меню GRUB, Application ID ISO,
  первая строка /etc/motd) берётся из `config/build.yaml`
  (`distro.version`) вместо литерала. В 1.3.1 меню GRUB внутри ISO
  говорит «1.2.9», /etc/motd установленной системы — «1.2.9» (оба
  найдены скриншотами стенда, спека 1.3.2-iso-version-strings) — тот же
  хардкод, из-за которого 1.3.0 получил чужие имена ассетов. Теперь имя
  файла, меню GRUB, Application ID и motd — из одного ключа
  конфигурации; пустой `version:` останавливает сборку с ошибкой.

## 1.3.1 (2026-11-17)

- Сборка: имя ISO больше не захардкожено в `scripts/50-iso.sh` — берётся
  из `config/build.yaml` (`output.iso_name`). В 1.3.0 релиз собрался

  релиз заменяет 1.3.0. Функциональных изменений нет (та же кодовая
  база + строки версии).

## 1.3.0 (2026-11-17)

- Зеркало двух дисков (эпик #36, спека mirror-two-disk, ADR-0004):
  разметка ESP+PV → vg0 (root/data, linear или raid1 по выбору в
  мастере) → Btrfs с прежними метками; autoinstall: `mirror`,
  `mirror_disk`, `system_size_mib`. Полевые данные: двухдисковое
  железо флота — штатная конфигурация.
- Degraded-boot: хук local-block активирует vg0 в initramfs
  (штатная автоактивация udev работает только для полной VG); ESP
  в fstab с `nofail` — без этого загрузка уходит в emergency mode.
- ESP-B на втором диске (метка `VLANIT-ESPB`, ≤11 символов) + UEFI-
  запись на оба диска (`efibootmgr` в составе системы).
- vlanit-doctor: проверки `lvm-layout` и `lvm-mirror-health`
  (SKIP на системах до введения LVM — старые установки валидны).
- Установщик: минимальный размер диска выводится из конфигурации
  (раньше захардкожен 50 ГиБ); команды хранилища завершаются
  диагностикой `VLANIT_INSTALL_FAILED`, а не молчаливым обрывом.
- Тестовая инфраструктура: сценарий mirror (4 фазы: установка на
  зеркало, проверки агента, degraded-загрузка со второго диска,
  замена диска), `regress-full.sh`, unit-тест disk-lib; агент —
  55 проверок.
- Исправления по результатам стенда (17 дефектов): метка ESP-B
  обрезана до лимита FAT (раньше установка обрывалась без сообщения),
  partprobe, паддинг `lvs --noheadings`, locale `sync_percent`,
  общий NVRAM фаз сценария, отказ тестов от `/tmp` хоста.

Тестирование (QEMU/KVM, UEFI): полный регресс Т1–Т9 и mirror
(4 фазы, включая degraded-загрузку и замену диска) — PASS,
55 проверок агента, 0 FAIL. Фазы mirror — на дисках 13 ГиБ
(root 3 ГиБ); продакшн-геометрия (≥50 ГиБ) — полевой прогон (#42).

## 1.2.9 (2026-11-15)

- АТС стартует после перезагрузки (issue #34): служба
  `vlanit-atc-secret` создаёт Podman secret до старта контейнера,
  зависимость от firstboot убрана — systemd больше не удаляет job
  mikopbx из-за цикла порядка загрузки.
- nftables: фильтр API АТС с loopback (только root) перенесён до
  `iifname lo accept` — раньше accept срабатывал первым и API без
  токена был открыт любому локальному пользователю.
- Бэкап: пароль веб-админа (`/etc/vlanit/atc-admin-password`) исключён
  из архива /etc — после восстановления пароль ротируется автоматически.
- Тест-агент: ручной старт АТС убран (маскировал дефекты загрузки),
  +2 проверки (atc-secret-service, no-ordering-cycle).

Тестирование (QEMU/KVM, UEFI): агент PASS, перезагрузочная фаза без
ручного старта АТС.

## 1.2.8 (2026-11-14)

- Provisioning MikoPBX: маркер `/.dockerenv:ro` (issue #10, полевой
  фидбек). Без него DockerCloud не применяет env (имя/порты/пароль из
  мастера). Upstream: mikopbx/Core#1104.
- SSH host keys генерируются при установке (issue #17): sshd стартует
  с первой загрузки без падений; drop-in сбрасывает ExecStartPre и ставит
  `ssh-keygen -A` до `sshd -t`.
- Часовой пояс АТС = пояс устройства (issue #18): `/etc/localtime` и
  `TZ` проброшены в контейнер, heal выравнивает `PBXTimezone` через
  REST v3 (time-settings).
- Безопасность (фидбек, не issue): пароль веб-админа перенесён из quadlet
  в Podman secret (`Secret=`, источник — `/etc/vlanit/atc-admin-password`
  0600); API АТС с loopback без токена ограничен root (`meta skuid != 0`).
- `vlanit-doctor` (issue #9): диагностика установленной системы по
  группам (система, диски/Btrfs, сеть, firewall, SSH, MikoPBX, журналы,
  обновления), вывод OK/FAIL/SKIP, `--quiet` / `--fix-hints` / `--json`,
  код возврата 0/1. Проверки агента и doctor читают одну библиотеку
  `/opt/vlanit/lib/checks.sh`; unit-тесты tests/unit/test-doctor-lib.sh.
- Самолечение пароля веб-админа АТС (issue #10, обход upstream-бага
  MikoPBX): служба `vlanit-atc-password-heal` на каждой загрузке проверяет
  логин паролем из quadlet и при сбросе применяет пароль через REST v3
  (PATCH general-settings, localhost bypass).
- Ядро 6.12.117+deb13-amd64.

Тестирование (QEMU/KVM, UEFI): 49 проверок агента PASS, 0 WARN.
