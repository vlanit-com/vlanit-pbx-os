# Зеркалирование двух дисков: LVM mirror под Btrfs

Статус: спека. Реализация: коммиты в feature/two-disk-mirror (#37, #38);
после приёмки стендом спека приведена к as-built (фактические отличия
ниже). Связанные документы: `docs/adr/0004`,
`docs/architecture.md`, README «Системные настройки по умолчанию».

## As-built (по результатам стенда)

- Метка второго ESP — `VLANIT-ESPB` (не `VLANIT_EFI_B`): mkfs.vfat
  принимает метки ≤11 символов; 12-символьная метка обрывала установщик
  молча через `set -e` (команды хранилища теперь завершаются `|| die`,
  найдено стендом Т-mirror).
- Проверка `lvm-layout` у агента: SKIP на legacy-схеме (Btrfs на
  разделах без LVM) — старые установки валидны.

## Корень

ТЗ §6 проектировало установку под один диск («Весь выбранный внутренний
диск»). **Подтверждено (полевые данные, 15.11.2026): устройства флота
эксплуатируются с двумя дисками** — это штатная конфигурация, не эфемерный
сценарий. Старый стик ставит на них md0 RAID1; установка VLANit PBX OS
без зеркала = потеря отказоустойчивости на действующем флоте, поэтому
зеркало — блокер миграции (эпик #36). Решённый сценарий использования: **отказоустойчивость** — смерть
одного диска не роняет телефонию; бокс продолжает работать на втором,
диск меняется без переустановки и без остановки АТС дольше одной перезагрузки.

Контекст развилки (фиксация решения владельцем): софт-рейд нужен
(зеркало), mdadm не вводим, **LVM вводится** — он становится единым слоем
томов под существующим Btrfs. Стек на целевом устройстве меняется:
`разделы → Btrfs` становится `разделы → LVM → Btrfs`.

## Принятое решение

### Дисковая схема

Оба кандидата размечаются одинаково; размер LV-легов — по меньшему диску
(зеркало возможно только в пределах минимального члена; разница ёмкостей
остаётся незадействованной — предупреждение в мастере).

| Раздел | Каждый диск | Назначение |
|---|---|---|
| p1 | 1 GiB, FAT32 (EF00) | ESP: GRUB + fallback `BOOTX64.EFI` (на оба диска) |
| p2 | остаток | PV в VG `vg0` |

LV (оба — `raid1`, по легу на каждый PV):

| LV | Размер | ФС | Содержимое |
|---|---|---|---|
| `vg0/root` | 40 GiB | Btrfs (label `vlanit-system`) | `@`, `@var_log`, `@snapshots` |
| `vg0/data` | остаток мин. диска | Btrfs (label `vlanit-data`) | `mikopbx-cf`, `mikopbx-storage`, `.snapshots` |

Подтверждение: существующий тулинг определяет ФС по меткам
(`vlanit-system`/`vlanit-data`) — `snapshots/vlanit-snapshot`,
`vlanit-update`, `vlanit-rollback`, `vlanit-backup`, doctor. Метки
сохраняются на Btrfs поверх LV, поэтому эти инструменты не меняются.

### Однодисковый случай — та же схема, linear

Один диск: один PV, те же LV типа `linear`. Кодовый путь установщика
единый (ветвится только тип LV и наличие второго ESP), появляется
возможность онлайн-растить LV/потом добавить второй диск в зеркало
(`lvconvert --type raid1 --alloc anywhere` + второй PV). Цена — новый
слой в однодисковой конфигурации, признаём.

### Деградация и загрузка с умершим диском

- Дефолт активации LVM — `complete`: с отсутствующим PV raid-LV не
  активируется. Требуется `degraded`/`partial`-активация. Точный механизм
  для initramfs-tools (drop-in хука lvm2 / `lvm.conf` внутри initramfs /
  опции vgchange) **не выбираем по памяти** — определяется в реализации
  и обязателен к проверке на стенде: установка → отключение диска A →
  перезагрузка → система работает.
- fstab: по UUID btrfs-ФС (как сейчас), btrfs монтируется обычно —
  `degraded`-опция btrfs не нужна (btrfs видит одно устройство; избыточность
  ниже, в LVM).
- GRUB ставится на ESP обоих дисков (повторный `grub-install` + копия
  fallback); при пропаже любого диска firmware грузит ESP другого.
- Замена диска (runbook в wiki): диск → `pvcreate` →
  `lvconvert --replace <oldpv> vg0/root vg0/data` → resync в фоне
  (проверить точный синтаксис на стенде; зафиксировать в runbook).

### Установщик

- Два и более кандидатов → экран выбора режима: «Один диск» /
  «Зеркало двух дисков» (выбор второго диска). Разный размер — предупреждение
  о неиспользуемом остатке большего диска.
- autoinstall.yaml: `disk:` (как сейчас) + опционально `mirror_disk:` /
  `mirror: true`; защиты — оба диска в списке кандидатов, оба чистые,
  `confirm: yes` как сейчас.
- Минимальный размер при зеркале: 2× разметка? Нет — по-прежнему ≥ 50 GiB
  (суммарно LV те же), проверка по меньшему диску.

### Изменения по коду (границы)

- `installer/lib/disk.sh` — разметка второго диска, pvcreate/vgcreate/
  lvcreate (тип по режиму).
- `installer/lib/deploy.sh` — ESP-B, mkfs.btrfs на LV, fstab (UUID без
  изменений логики), LVM-активация в initramfs, GRUB на оба ESP.
- `rootfs/` — drop-in lvm2/initramfs-конфигурация для degraded-активации;
  doctor-проверка `lvs` (тип raid1, состояние легов) в `lib-checks.sh`.
- Golden Image: добавить `lvm2` (+ dm-raid модуль ядра в initramfs).
- `scripts/test-qemu.sh` — сценарий `mirror` (см. «Проверка»).
- Тест-агент (`rootfs/vlanit-test-agent.sh`): проверки зеркала
  (lvs-raid1, оба лега) и degraded-загрузки.

## Отклонённые альтернативы

- **mdadm + Btrfs сверху** — тот же класс доступности, но второй стек
  управления поверх нового слоя LVM: два RAID-механизма вместо одного.
  К тому же с Btrfs-on-mdadm самовосстановление по контрольным суммам
  btrfs не работает (btrfs видит одно устройство) — главное btrfs-преимущество
  теряется так же, как с LVM mirror, но с лишним слоем.
- **Нативный Btrfs RAID1** (`-d raid1 -m raid1` на два раздела, без LVM):
  минимальная сложность, работает self-heal btrfs, замена диска —
  `btrfs replace`. Отклонено владельцем: LVM выбран как единый слой томов
  (resize, будущие сценарии пулов). Цена решения зафиксирована в ADR-0004:
  btrfs видит single-device → self-heal по контрольным суммам btrfs
  недоступен (битые чтения перекрываются легами dm-raid на уровне I/O-ошибок,
  без проверки сумм), scrub btrfs сохраняется только как детектор.
- **LVM linear без зеркала** — нет отказоустойчивости, не соответствует
  выбранному сценарию.
- **Зеркало только Data, root одиночный** — смерть диска с root = простой
  АТС, зеркало бессмысленно.
- **Менять ТЗ-структуру под разные схемы для 1/2 дисков** — отклонено:
  единый кодовый путь (см. «Однодисковый случай»).

## Проверка

1. QEMU-сценарий `mirror` (два virtio-диска):
   a. установка с mirror → тест-агент: lvs тип raid1, оба лега, subvolumes
      смонтированы, MikoPBX работает;
   b. выключение, удаление диска A → загрузка → система на диске B
      (degraded), АТС поднялась;
   c. вернуть диск A → resync, статус зеркла чистый;
   d. замена диска B на новый (новый vda) → восстановление зеркла по
      runbook-процедуре.
2. Однодисковая установка (регрессия t8/основной сценарий): linear-LV,
   все существующие проверки агента PASS.
3. Ручной прогон на железе с двумя SSD — записать результат в notes релиза
   (как полевой тест; в автотесты не входит).
4. wiki-runbook «Замена диска в зеркале» — по факту проверенной на стенде
   процедуре (обязательный шаг приёмки).

## Известные проблемы (по результатам стенда)

1. **Зависание установки на записи fstab / blkid при простаивающем
   dm-raid1** (прогоны #12–#14, малый профиль 13 ГиБ): начальный sync
   завершается за ~1 минуту, массив простаивает во время записей
   установки → непрерывное зависание записи на Btrfs-поверх-raid1
   (хост idle, гость жив, wedge на уровне ядра). При продакшн-размерах
   дисков (≥50 ГиБ, sync ~10 мин) синхронизация перекрывает установку
   и зависание не воспроизводилось (#6/#7). Открытый вопрос уровня
   ядра (dm-raid1 × btrfs commit); митигация — не использовать
   малый профиль для приёмки, полный размер — полевой тест (#42).
2. **lvs/pvs в окне ранней загрузки** — аномалия пустого вывода pvs
   при работающих lvs/vgs (зафиксирована DIAG); обход — счётчики через
   vgs (pv_count − vg_missing_pv_count). Требует расследования при
   первом повторении на регулярной регрессии.
