# 1.3.2 — верификация и доводка фирменной темы Plymouth

Дата: 2026-11-18. Без пересборки ISO: статика по собранным rootfs + runtime
в QEMU (KVM, OVMF, screendump через monitor-сокет, shell через `init=/bin/sh`
и sendkey). Два независимых прогона (verply, plymouth) сошлись на выводах
ниже; фиксы — коммит с этим spec.

## Корень вопроса

Тема `vlanit` (two-step, 0x09090b / 0xd4aa6a, watermark из логотипа,
`branding/vlanit.plymouth`, коммит 17773f6) должна показывать при загрузке
фирменный сплэш. Проверяем оба носителя: golden rootfs (установленная
система) и live rootfs (установщик с ISO).

## Что проверено

### 1. Golden (`build/rootfs/golden`) — установленная система: цепочка полная

- Тема на месте: `/usr/share/plymouth/themes/vlanit/` — `vlanit.plymouth`,
  `watermark.png` (12 КБ, из SVG логотипа), анимация `animation-*.png` (36
  кадров), `throbber-*.png` (30), диалоги spinner (`entry.png`, `bullet.png`,
  `capslock.png`, `keyboard.png`, `lock.png`, `keymap-render.png`).
- Конфиг на месте: `/etc/plymouth/plymouthd.conf` → `Theme=vlanit`,
  `ShowDelay=0` (на диске установленной системы проверен из `init=/bin/sh`).
- Hook initramfs-tools подхватит тему: штатный
  `/usr/share/initramfs-tools/hooks/plymouth` определяет тему через
  `plymouth-set-default-theme` (читает `plymouthd.conf` → `vlanit`).
  Установщик выполняет `update-initramfs -u -k all` в chroot цели
  (`installer/lib/deploy.sh:215`). Состав initramfs установленной системы
  проверен изнутри живой системы: 100 файлов plymouth, включая
  `usr/share/plymouth/themes/vlanit/watermark.png` и `vlanit.plymouth`.
- Cmdline: `GRUB_CMDLINE_LINUX_DEFAULT="quiet splash console=tty0
  console=ttyS0,115200"` (`installer/lib/deploy.sh:130`); фактический
  `grub.cfg` на установленном диске (скриншот редактора GRUB) содержит
  `quiet splash` и обе консоли.
- systemd-обвязка штатная: `plymouth-start` (sysinit), `plymouth-quit` /
  `plymouth-quit-wait` (multi-user), `plymouth-reboot` / `-halt` /
  `-poweroff` / `-kexec` в целях остановки.

Вывод: дефектов в цепочке «конфиг → hook → initramfs → cmdline → systemd»
нет — она работает и создаёт условия для сплэша на загрузке, перезагрузке
и выключении.

### 2. Runtime установленной системы в QEMU — сплэш не рисуется, найден корень

Стенд: диск установленной 1.3.1 (QCOW2), загрузка по умолчанию и с
`plymouth.debug` / `init=/bin/sh` (правка cmdline в редакторе GRUB).

- При обычной загрузке графический сплэш ни разу не появился: кадры с
  шагом 0,8–0,9 с покрывают всё окно загрузки — консоль остаётся текстовой,
  сообщения systemd видны до `plymouth-quit` (~8 с до multi-user).
- Дебаг plymouthd (`plymouthd --mode=boot --attach-to-session --debug`)
  показал причину: инициализируются только текстовые дисплеи
  (`adding 0x0 text display`, `adding 160x50 text display` для ttyS0/tty1),
  графический DRM-рендерер не создан — splash нечем рисовать.
- В initramfs установленной системы **нет GPU-модулей**
  (`lsinitramfs … | grep -E 'bochs|i915|amdgpu'` → пусто; DRM-ядро есть,
  61 файл). `MODULES=most` GPU-драйверы не включает → раннего KMS нет,
  plymouth в initramfs сидит на текстовом фолбэке.
- Проверка направления фикса вживую: `echo bochs >
  /etc/initramfs-tools/modules` + `update-initramfs -u` в установленной
  системе → пересобранный initrd содержит bochs. Контрольная загрузка
  прервана (стенд walk132c удалён параллельным прогоном) — визуально
  подтвердить отрисовку в QEMU не успели.

### 3. Live (`build/rootfs/live`) — Plymouth отсутствовал полностью (дефект)

- В `LIVE_PACKAGES` (`scripts/20-live-rootfs.sh`) не было `plymouth`/
  `plymouth-themes`: ни бинарей, ни тем, ни `/etc/plymouth/plymouthd.conf`
  в live rootfs; live initrd (распакован) — 0 файлов plymouth.
- В cmdline ISO (`scripts/50-iso.sh`) не было `splash`
  (`ro quiet loglevel=3 console=tty0 console=ttyS0,115200`).
- Runtime (загрузка boot.iso 1.3.1 в QEMU): после фирменного меню GRUB —
  чёрный экран без логотипа/прогресса до TUI установщика. Логотип «на
  ранних скриншотах» — фон меню GRUB (`vlanit-grub-bg.png`), не Plymouth.
- Конфликта с TUI нет: `vlanit-installer.service` уже сидит
  `After=… plymouth-quit-wait.service` и конфликтует с getty@tty1 —
  plymouth-quit вернёт консоль, установщик отрисуется штатно.

## Фиксы (as-built)

1. **Live получил Plymouth**: `plymouth plymouth-themes` в `LIVE_PACKAGES`
   (20-live-rootfs.sh), установка темы + `plymouthd.conf` в live rootfs,
   `splash` добавлен в cmdline пункт «Установить … (UEFI)» (50-iso.sh;
   отладочный пункт без splash — он для диагностики). В фазе live-initramfs
   plymouth по-прежнему не запускается (busybox `vlanit-init` не вызывает
   plymouthd) — сплэш живёт от switch_root до plymouth-quit/multi-user.
2. **GPU KMS-модули в initramfs установленной системы**: новый
   `rootfs/etc-initramfs-tools-modules` → `/etc/initramfs-tools/modules`
   (ast, i915, amdgpu, radeon, bochs, virtio-gpu), устанавливается в
   golden (10-golden-rootfs.sh). initramfs-tools включит и загрузит их при
   сборке initrd установщиком (`update-initramfs` в deploy.sh:215).
   Потребитель — plymouth в initramfs: без раннего KMS сплэш деградирует
   в текст (п. 2 проверки).
3. **Дублирование убрано**: блок установки темы вынесен в общий
   `scripts/install-plymouth-theme.sh`, вызывается из 10-golden и 20-live
   (единый источник логики темы).
4. **Тест-агент** (`rootfs/vlanit-test-agent.sh`): проверки
   `plymouth-initramfs-gpu-modules` и `plymouth-cmdline-splash` рядом с
   существующей `plymouth-theme-vlanit`.

Каждый конфиг с потребителем: `plymouthd.conf` читается plymouthd
(`--mode=boot/shutdown`), `modules` — initramfs-tools при mkinitramfs /
update-initramfs, `splash` в cmdline — условие старта plymouthd
(`ConditionKernelCommandLine=!nosplash` и логика show-splash).

## Открытые пункты (честно)

- Визуальное подтверждение отрисовки сплэша — на железе или в QEMU с
  ранним KMS: прогон оборвался на удалении стенда. До подтверждения
  остаётся возможность, что отрисовка на simpledrm/EFI-fb упрётся в ещё
  не выявленную причину (в стенде plymouthd не создал DRM-рендерер даже
  при наличии `/dev/dri/card0`).
- Объём live initrd вырастет на ~1,5 МБ (hook plymouth кладёт тему в
  initramfs, а busybox-init её не использует) — осознанно оставлено,
  дешевле чем отдельный выключатель хука.
- Shutdown/reboot-сплэш (юниты plymouth-halt/reboot/poweroff) проверен
  по конфигурации, визуально не фиксировался.
