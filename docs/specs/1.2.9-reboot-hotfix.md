# Спека 1.2.9 — hotfix: цикл порядка загрузки (#34) + безопасность

Ветка `hotfix/1.2.9-reboot`, зонтик — issue #35. Дедлайн по полевому
запросу: пн 18:00 Дубай.

## 1. АТС не стартует после перезагрузки (issue #34)

**Корень.** В 1.2.8-r2 quadlet получил `After=vlanit-firstboot.service`
(гонка secret при загрузке). firstboot — `After=multi-user.target` +
`WantedBy=multi-user.target`. Цикл: multi-user → mikopbx → firstboot →
multi-user. systemd ломает его удалением job'ов: на первой загрузке
АТС стартует руками из firstboot.sh, на последующих firstboot пропущен
(ConditionPathExists) и job mikopbx удалён — АТС не стартует никогда.
Выбор удаляемого job недетерминирован: в нашем QEMU удаляли heal, у
заказчика — mikopbx. Поэтому регрессия 1.2.8 «прошла», а в поле сломалось.

**Решение.** Зависимость mikopbx от firstboot убрана. Создание Podman
secret вынесено в отдельную раннюю службу:

- `vlanit-atc-secret.service`: `DefaultDependencies=no`,
  `After=local-fs.target`, `Before=mikopbx.service`. Не зависит от
  multi-user.target → цикла нет. Идемпотентна: `podman secret exists`
  → выход; файла пароля нет (восстановление из бэкапа) → генерирует
  новый (provisioning АТС применит его из env при старте).
- quadlet: `After=network-online.target vlanit-atc-secret.service`.
- firstboot: создание secret удалено, осталась диагностика.

**Почему не вернуть «как в 1.2.7» (After=network-online только).**
Гонка первой загрузки вернётся: mikopbx (auto-enable) стартует до
создания secret и падает. atc-secret решает обе проблемы: и гонку
(Before=mikopbx), и цикл (нет зависимости от firstboot/multi-user).

## 2. nft loopback-фильтр не срабатывал (фидбек, не issue)

**Корень.** Правило `iifname lo meta skuid != 0 drop` стояло ПОСЛЕДНИМ
в chain input; `iifname "lo" accept` выше принимал весь loopback раньше.
Полевой факт: API без токена с 127.0.0.1 отдаёт 200 для root, vlanit
и nobody.

**Решение.** Правило перенесено ДО `iifname "lo" accept`. Порядок:
established → skuid-drop (lo:80,443 non-root) → lo accept → остальное.
Проверено: `nft -c` валиден. Службы VLANit (heal/doctor) — root, не
затронуты.

## 3. Пароль веб-админа в бэкапе (фидбек, не issue)

`vlanit-backup` архивировал /etc целиком → файл пароля (0600) уезжал
на USB. Исключён `--exclude='etc/vlanit/atc-admin-password'`.
Побочное следствие задокументировано: после восстановления из бэкапа
пароль ротируется (atc-secret генерирует новый, DockerCloud применяет
из env). Фактический пароль — в /etc/vlanit/atc-admin-password (0600).

**Оставшиеся экспозиции пароля (upstream MikoPBX, зафиксировано, не
чиним сами):** баннер АТС «Password: …» в журнале контейнера;
CloudInstanceId в БД АТС. Оба — поведение образа MikoPBX, ретранслируем
в upstream (mikopbx/Core#1104).

## 4. Тест-агент: снята маскировка дефектов загрузки

- Ручной `systemctl start mikopbx` в агенте убран — АТС обязана
  подняться сама (иначе дефект порядка загрузки маскируется, ровно как
  в #34). Агент только ждёт активности (до 2 мин).
- Новые проверки: `atc-secret-service` (enabled),
  `no-ordering-cycle` (в журнале загрузки нет «ordering cycle»).

## Проверка

Регрессия QEMU install: фаза перезагрузки теперь честная (без ручного
старта). Ожидание: все проверки PASS, включая reboot-mikopbx-active и
no-ordering-cycle, на ОБЕИХ загрузках.
