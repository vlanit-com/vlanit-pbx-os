# Спека: версия в строках артефактов сборки из config/build.yaml (1.3.2)

## Корень изменения

Проверка опубликованного v1.3.1 (2026-11-17, скриншоты QEMU-стенда)
показала два места с чужой версией «1.2.9» внутри артефактов релиза 1.3.1:

1. Пункты меню GRUB внутри ISO и Application ID ISO (поле `-A` xorriso).
   При этом имя файла ISO и ассеты релиза — правильные (`1.3.1`).
2. Первая строка `/etc/motd` установленной системы
   («VLANit PBX OS 1.2.9 — Debian 13 + Podman + MikoPBX», найдено
   скриншотом консоли после установки со стенда).

Тот же корень, что и у дефекта v1.3.0 (ассеты с именем 1.2.9): версия
была захардкожена в скриптах сборки. Исправление v1.3.1 убрало хардкод
только из имени файла (строка `iso_name`), строки меню GRUB,
Application ID и motd остались литералами.

## Решение (as-built)

Что · значение · где · как проверяется:

- Версия в меню GRUB · из `distro.version` config/build.yaml
  (подстановка `$VERSION` в heredoc grub.cfg) · `scripts/50-iso.sh` ·
  после сборки: `7z e -so <iso> boot/grub/grub.cfg | grep menuentry` —
  строки совпадают с версией в build.yaml.
- Application ID ISO · `-A "VLANit PBX OS $VERSION"` · тот же скрипт,
  вызов xorriso · `xorriso -indev <iso> -pvd_info` или тот же 7z-вывод
  по заголовку тома.
- Версия в /etc/motd · из `distro.version` config/build.yaml,
  placeholder `@VLANIT_VERSION@` в `rootfs/etc-motd` рендерится
  sed при сборке golden · `scripts/10-golden-rootfs.sh` · после сборки:
  первый строка `/etc/motd` в golden совпадает с версией в build.yaml.
- Строка UEFI-режима в мастере · «VLANit PBX OS $manifest_version
  устанавливается только на UEFI» (был литерал «1.0») ·
  `installer/vlanit-installer` · диалог не-UEFI показывает версию текущего
  релиза.
- Литералы версии в стенде · `scripts/test-qemu.sh`: имя ISO и -A
  тестового Application ID вычисляются из `config/build.yaml` (тот же
  sed-однострочник, что в 50-iso.sh) · аудит grep `1\.3\.1` по скриптам
  после правки чист.
- Шапка vlanit-doctor · `OS: $PRETTY_NAME` из /etc/os-release в
  plain-отчёте (в полевых логах версия раньше не определялась) ·
  `rootfs/vlanit-doctor` · вывод doctor начинается со строки версии.
- Отсутствие хардкода · grep `1\.2\.9` по scripts/, config/, rootfs/,
  live/, installer/, provisioning/ даёт только комментарии-историю ·
  тот же grep перед коммитом.
- Отказ сборки без версии · `version:` пуст/отсутствует → exit 1
  с сообщением `[iso] ОШИБКА` · preflight в начале `50-iso.sh`.

Единый источник версии: `distro.version` в `config/build.yaml`
(тот же ключ, из которого os-release и имена ISO).

## Отклонённые альтернативы

- Оставить литерал и править руками перед каждым релизом — уже дважды
  дало релиз с чужой версией (1.3.0 — имена ассетов, 1.3.1 — меню GRUB).
- Брать версию из git-тега (`git describe`) — сборка в CI идёт на
  коммите тега, но локальные сборки из не-тегового состояния получили бы
  мусорную строку; build.yaml уже обязателен для имени ISO.

## Проверка (факт)

- `grep -rn "1\.2\.9" scripts/ config/ rootfs/ live/ installer/
  provisioning/` — только комментарии (`40-staging.sh`, `50-iso.sh`).
- `bash -n scripts/50-iso.sh` — синтаксис в порядке.
- Полная пересборка ISO в рамках следующего релизного тега: пункты меню
  GRUB и Application ID совпадают с версией тега (открытый пункт релиза
  1.3.2 — подтвердить на факте публикации).

## Открытый пункт

Релиз v1.3.1 опубликован с меню GRUB «1.2.9» и motd «1.2.9» — оба
исправления войдут в 1.3.2. Тег v1.3.1 по правилу релизов не меняется;
в Release Notes 1.3.1 добавлена честная сноска.
