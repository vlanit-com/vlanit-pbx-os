# Спека 1.3.2 — issue #44 (мастер: короткий пароль обрывал установку) и #45 (heal задерживает загрузку)

Оба тикета подтверждены в коде на master (2026-11-18). Фиксы минимальные,
без изменения поверхности настроек.

## 1. Мастер: пароль короче 8 символов обрывает установку (issue #44)

**Корень.** В `installer/vlanit-installer` (экран параметров системы) после
`passwordbox` стояла проверка `[ "${#ADMIN_PASS}" -ge 8 ] || { msgbox; exit 1; }`.
То же для часового пояса: `[ -f /usr/share/zoneinfo/$TZ_NAME ] || { msgbox; exit 1; }`.
Ошибка ввода убивала весь установщик: на экране оставался чёрный tty, из
которого оператор без перезагрузки не выйти.

**Решение (as-built).** Проверки обёрнуты в циклы `while :`:

- пароль: `passwordbox` → если короче 8 символов — msgbox «Пароль короче 8
  символов.» и возврат в поле ввода;
- часовой пояс: `inputbox` → пока `/usr/share/zoneinfo/$TZ_NAME` не
  существует — msgbox «Неизвестный часовой пояс: $TZ_NAME» и повторный ввод.

Отмена (Esc / «Отмена») по-прежнему выходит из установщика: `dialog ... ||
exit 1` осталось первой командой в теле цикла. Autoinstall-ветка
(validation `die`) не тронута — там обрыв с диагностикой корректен.

**Отклонённые альтернативы.**

- *Проверка длины внутри dialog (`--max-len` и т.п.)*: у `passwordbox` нет
  штатной валидации; костыли с промежуточными экранами читаются хуже цикла.
- *Переход к следующему экрану с post-check перед записью*: откладывает
  ошибку далеко от её причины, усложняет код.

## 2. vlanit-atc-password-heal задерживает загрузку ~2,5 мин (issue #45)

**Корень.** `rootfs/vlanit-atc-password-heal.service`: `Type=oneshot`,
`After/Wants=mikopbx.service`, `[Install] WantedBy=multi-user.target`.
multi-user.target — наборной: он ждёт завершения всех wanted-юнитов,
включая oneshot-heal (~2,5 мин на медленной загрузке — контейнер MikoPBX
стартовал долго). `vlanit-firstboot.service` (`After=multi-user.target`)
стартовал только после heal; при раннем отключении питания firstboot-done
не записывался.

**Решение (as-built).** В `[Install]` заменено `WantedBy=multi-user.target`
→ `WantedBy=mikopbx.service`. systemd допускает Wants-зависимость от
сервиса: при старте `mikopbx.service` подтягивается heal, выполняется
`After=mikopbx` в прежнем порядке (самолечение — после старта АТС),
а multi-user.target его не ждёт → firstboot стартует сразу после
multi-user, не блокируется heal.

Механизм enable: `scripts/10-golden-rootfs.sh` делает `systemctl enable`
в chroot golden rootfs — он читает `[Install]` и создаст
`mikopbx.service.wants/vlanit-atc-password-heal.service`. Отсутствие
`mikopbx.service` на момент enable не мешает: enable создаёт wants-симлинк
без проверки существования цели; сам юнит появляется из quadlet-генератора
в `/run/systemd/generator/` при загрузке. `rootfs/99-vlanit.preset`
(`enable vlanit-atc-password-heal.service`) тоже следует `[Install]` —
менять не нужно. Проверка агента `atc-heal-service`
(`systemctl is-enabled`) остаётся зелёной: симлинк существует.

**Отклонённые альтернативы.**

- *DefaultDependencies=no (как у vlanit-atc-secret.service)*: лечит
  ожидание, но ломает семантику «heal — после старта АТС»: юнит ушёл бы
  раньше mikopbx, самолечение стало бы бесполезным. Образец atc-secret
  не копируем намеренно — там другой смысл (secret нужен ДО контейнера).
- *Перевод heal из oneshot в forking/simple (фоном)*: теряется контроль
  завершения, усложняется диагностика; не решает корень (ожидание
  multi-user переносится на фоновый процесс — хуже).
- *WantedBy=basic.target*: heal стартовал бы ДО сети/контейнеров, рушит
  After=mikopbx логику сильнее.

`vlanit-atc-secret.service` (DefaultDependencies=no, issue #34) не
изменён и не затронут: после переключения heal на `mikopbx.service.wants`
цикла порядка между heal / atc-secret / mikopbx / multi-user не
возникает (heal зависит только от mikopbx, atc-secret — Before=mikopbx).

## Проверка

- `bash -n installer/vlanit-installer` — синтаксис валиден.
- `systemd-analyze verify` обоих юнитов в chroot целевого rootfs
  (golden) — exit 0, предупреждений нет.
- QEMU/KVM (ISO 1.3.2 + подменённые артефакты: squashfs с новым
  установщиком, golden.tar.zst с новым unit и wants-симлинком — то, что
  сделает пересборка golden/initrd):
  - #44: мастер → пароль 4 символа → msgbox → Enter → повторный
    passwordbox (скриншот) → нормальный пароль → установка продолжается
    (serial: этапы после повторного ввода).
  - #45: после установки — `systemd-analyze` (загрузка без ожидания
    heal), `systemctl show vlanit-atc-password-heal -p WantedBy`,
    отсутствие heal в `multi-user.target.wants/`, наличие симлинка в
    `mikopbx.service.wants/`, `is-enabled` = enabled.
- Полный цикл (пересборка golden + initrd из этого дерева) — на следующей
  полной сборке 1.3.2; runtime-поведение здесь проверено подменой
  артефактов, эквивалентной выводу `systemctl enable` с новым `[Install]`.
