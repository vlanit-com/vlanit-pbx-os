# Спека 1.3.0 — самолечение пароля АТС (issue #10) и vlanit-doctor (issue #9)

## 1. Обход upstream-бага: пароль веб-админа не переживает reboot

**Корень (подтверждён исходным кодом образа 2026.6.99):**
`DockerCloud::applyEnvironmentOverrides()` применяет env при каждом старте
контейнера, `CloudProvider` пишет `WEB_ADMIN_PASSWORD` (хэш) в БД. Но после
перезагрузки MikoPBX сбрасывает хэш на дефолтный пароль, а повторное
применение env-пароля не даёт результата (маркер `CLOUD_INSTANCE_ID` для
Docker не записывается — `shouldSetCloudInstanceId() == false`, конфликт
механизмов). Подтверждено полем: после reboot логин паролем из quadlet не
проходит, стандартный — проходит.

**Решение (as-built):** служба `vlanit-atc-password-heal.service`
(oneshot, `After=mikopbx.service`, каждая загрузка) → скрипт
`/opt/vlanit/vlanit-atc-password-heal.sh`:

1. Ждёт готовности приложения (баннер «All services are fully loaded»,
   до 10 мин).
2. Проверяет логин паролем из quadlet (`POST /pbxcore/api/v3/auth:login`,
   localhost bypass).
3. При FAIL — применяет пароль повторно через REST v3:
   `PATCH /pbxcore/api/v3/general-settings {"WEB_ADMIN_PASSWORD": ...}`
   (endpoint подтверждён исходным кодом: RestController GeneralSettings,
   `@ApiParameterRef(PbxSettings::WEB_ADMIN_PASSWORD)`).
4. Ждёт асинхронного применения (Redis-очередь, до 60 с) и перепроверяет
   логин; 3 попытки.
5. Флаг `/var/lib/vlanit/atc-password-broken` выставляется при детекте,
   снимается при успехе.

Почему служба, а не firstboot: сброс повторяется на каждой перезагрузке,
а firstboot — одноразовая (`ConditionPathExists=!firstboot-done`).

**Отклонённые альтернативы:** правка исходников образа MikoPBX (не
сопровождается, ломается при обновлении образа); применение пароля в БД
напрямую (не подтверждённая внутренность, применение асинхронное).

**Проверка:** агент `atc-heal-service` (enabled) + `reboot-api-login`
(логин после reboot — ожидаемый переход WARN→PASS после самолечения).
