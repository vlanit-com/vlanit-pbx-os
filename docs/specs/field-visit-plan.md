# План полевого выезда: приёмка VLANit PBX OS 1.4.1

Для исполнителя на объекте. Issues: **#42** (первый бокс), **#49** (GUI
на железе), **#14** (Plymouth). Эпик миграции: **#36**.

ISO: [v1.4.1](https://github.com/vlanit-com/vlanit-pbx-os/releases/tag/v1.4.1)
(`VLANit-PBX-1.4.1-amd64.iso`). Wiki: [Экраны установки](https://github.com/vlanit-com/vlanit-pbx-os/wiki/Installation-Screens),
[Быстрый старт](https://github.com/vlanit-com/vlanit-pbx-os/wiki/Quick-Start).

Ожидаемое время: **3–5 ч** чистой работы (+ выдержка ≥24 ч отдельно).

---

## 0. До выезда (офис / дома)

- [ ] Скачать ISO 1.4.1 + `.sha256` + `.asc`
- [ ] `sha256sum -c …iso.sha256` и GPG
      (`gpg --verify` с `rootfs/etc-vlanit-release.pub` из репо)
- [ ] Записать USB (`dd` / Rufus DD / `write-usb.sh`)
- [ ] Ноутбук: SSH-клиент, браузер, фотоаппарат/телефон
- [ ] Запасной USB, HDMI/VGA-кабель, отвёртка под SSD
- [ ] Если будет перенос АТС со старого бокса — заранее снять backup
      (issue #41; иначе прогон без миграции данных)

Железо на объекте: **2× SSD ≥64 ГиБ**, UEFI, сеть, монитор/консоль.

---

## 1. Установка с GUI (#42 + #49)

Цель: мастер на реальном framebuffer, не только QEMU.

1. Boot USB **UEFI** → GRUB «Установить … (UEFI)».
2. **Plymouth** (#14): во время загрузки live — виден логотип VLANit?
   Фото. Если чёрный экран/текст — зафиксировать модель GPU (`lspci | grep -i vga` после).
3. Стартовал ли **GUI** (не TUI/dialog)? Если fallback — почему
   (нет `/dev/fb0`? netsurf упал?) → в отчёт.
4. Пройти экраны (скрины/фото ключевых):
   - оборудование  
   - диск → режим **зеркало RAID1**, второй SSD  
   - сеть  
   - система (пароль ОС ≥ 8)  
   - WireGuard (можно «не включать» или вкл. для проверки)  
   - подтверждение → прогресс → завершение  
5. С экрана завершения сохранить: **IP**, URL веб-АТС, пароль веб
   (если автоген), WG pubkey (если вкл).
6. Reboot **с диска** (USB вынуть). Снова Plymouth (#14) — фото.

---

## 2. После firstboot (#42)

Под админом из мастера:

```bash
sudo vlanit-doctor --fix-hints
# на консоли с монитором (опционально):
# sudo vlanit-doctor --gui
systemctl is-active mikopbx
podman ps
# если WG включали:
sudo wg show
```

- [ ] SSH с ноутбука (root по SSH закрыт — ок)
- [ ] HTTPS веб-АТС, вход паролем из мастера
- [ ] `vlanit-doctor` — без неожиданных FAIL (WARN по degraded — только
      если диск уже изымали)

---

## 3. Зеркало на железе (#42 / D)

**Осторожно: изъятие диска — деградация.**

1. `sudo lvs -a -o+devices,health_status` — root/data = raid1; ESP на обоих.
2. Выключить → **изъять диск A** → включить.
3. Система грузится с B, АТС жива? `vlanit-doctor` может WARN — ок.
4. Выключить → вернуть/заменить диск → включить → дождаться resync
   (`lvs` / `sudo lvs -a`). Время resync — в отчёт.
5. Фото серийников дисков.

Runbook замены диска в wiki (#39) может быть ещё не готов — команды
только те, что уверенно знаете со стенда; иначе **не** экспериментировать
с `lvconvert` на живом боксе без связи с разработкой.

---

## 4. Выдержка (можно оставить на объекте)

- [ ] ≥24 ч: `vlanit-doctor --quiet` = 0 (или только ожидаемые WARN)
- [ ] Кнопка питания: короткое / длинное — поведение как задумано

Миграция данных со старого бокса (#41) и полная сверка паритета (#40) —
**отдельный блок**, не обязателен в этот выезд, если цель только
«первый бокс живой».

---

## 5. Что прислать обратно (отчёт)

В чат / issue #42 (и копии в #49, #14):

1. Модель железа, CPU/GPU, 2× SSD (модель, размер, серийники).  
2. Версия ISO (1.4.1), дата/время.  
3. GUI: да/нет; Plymouth live + после reboot: да/нет + фото.  
4. PASS/FAIL по шагам 1–3.  
5. Фото: GRUB, 2–3 экрана GUI, завершение, `lvs`, веб-АТС.  
6. Логи при FAIL: `/var/log/vlanit-install.log`, `journalctl -b -u mikopbx`,
   вывод `vlanit-doctor`.  
7. Открытые косяки — списком (не чинить всё на месте без спеки).

## Критерий успеха выезда

| Issue | Успех |
|---|---|
| #49 | GUI на ≥1 (лучше 2) моделях с фото |
| #14 | Plymouth виден на железе или зафиксирован FAIL + GPU |
| #42 | Бокс установлен зеркалом, firstboot ок, degraded-проверка сделана или осознанно отложена с причиной |

Полное закрытие #42 = ещё выдержка 24 ч + (по возможности) resync после
возврата диска. Автотесты QEMU **не** заменяют этот прогон.
