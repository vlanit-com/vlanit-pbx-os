# LVM mirror под Btrfs для двухдисковых устройств

Контекст: в устройствах бывает два диска (не эфемерный сценарий).
Выбранный сценарий — отказоустойчивость: смерть диска не роняет телефонию,
второй диск продолжает работу, замена без переустановки. Владелец решил:
LVM вводится в стек (ранее: разделы → Btrfs напрямую), софт-рейд нужен
(mdadm не вводится).

Решили: дисковая схема «LVM mirror под Btrfs» — на каждом диске ESP +
PV, VG `vg0`, LV `root` (40 GiB) и `data` типа `raid1` по легу на диск,
Btrfs с прежними subvolumes и метками поверх LV. Однодисковые устройства
используют ту же схему с LV типа `linear` (единый кодовый путь,
возможность вырасти в зеркало без переустановки). Загрузка с умершим
диском — через degraded-активацию LVM в initramfs (механизм определяется
в реализации и принимается только по результату стенда).

Почему: требование «диск умер → АТС работает» достижимо только
резервированием на уровне блочных устройств; LVM mirror закрывает его в
одном слое с управлением томами, который владелец хочет видеть в стеке в
принципе. Существующий btrfs-тулинг (снапшоты, OTA-откат, бэкап, doctor)
опирается на метки ФС — они сохраняются, инструменты не меняются.

Цена (осознанно принятая): btrfs поверх raid-LV видит одно устройство —
его контрольные суммы работают как детектор, но не как самовосстановление
(при ошибке чтения лега dm-raid перечитывает с другого лега, проверки
сумм при этом нет; нативный btrfs RAID1 самовосстанавливал бы молча).
Усложняется деградация: дефолт LVM (`complete`) с отсутствующим PV не
активирует raid-LV — требуется настройка initramfs (риск «не грузится
со второго диска» до тех пор, пока стенд не подтвердит).

Отклонённые варианты: **mdadm + Btrfs сверху** — второй RAID-стек поверх
вводимого LVM, self-heal btrfs всё равно недоступен; **нативный Btrfs
RAID1 без LVM** — минимальная сложность и self-heal, но владелец выбрал
LVM как единый слой томов (resize, будущие пулы); **LVM linear без
зеркала** — нет отказоустойчивости; **зеркало только Data** — смерть диска
с root роняет АТС. Спека: `docs/specs/mirror-two-disk.md`.
